# KREONYX CLI Agents Guide

## Overview

KREONYX CLI uses a multi-agent architecture where different agents handle specialized tasks. Agents can work independently or collaborate through the orchestrator.

## Built-in Agents

### build
The default agent for development work.
- **Mode**: Primary
- **Permissions**: Full access (read/write files, execute bash, etc.)
- **Use Case**: Writing code, fixing bugs, implementing features

### plan
Read-only agent for analysis and exploration.
- **Mode**: Primary
- **Permissions**: Read-only, asks permission for bash commands
- **Use Case**: Exploring unfamiliar codebases, planning changes

### orchestrator
Multi-agent coordinator for collaborative tasks.
- **Mode**: Primary
- **Permissions**: Manages collaboration sessions, delegates to subagents
- **Use Case**: Complex tasks requiring multiple specialized agents

### Subagents

#### implementer
Specialized for implementing code changes.
- **Mode**: Subagent
- **Parent**: orchestrator
- **Use Case**: Writing implementation code

#### integrator
Specialized for combining results from multiple sources.
- **Mode**: Subagent
- **Parent**: orchestrator
- **Use Case**: Merging parallel task results

#### reviewer
Specialized for code review.
- **Mode**: Subagent
- **Parent**: orchestrator
- **Use Case**: Reviewing code, providing feedback

#### debater
Specialized for structured debates.
- **Mode**: Subagent
- **Parent**: orchestrator
- **Use Case**: Discussing implementation approaches

## Orchestrator Agent

The orchestrator agent coordinates multi-agent collaboration through structured workflows.

### Creating Sessions

```typescript
import { Orchestrator } from "@/agent/orchestrator"

const session = await Orchestrator.createSession(orchestratorAgentId, {
  title: "Feature Implementation",
  description: "Implement new authentication system",
  participants: ["agent-1", "agent-2", "agent-3"]
})
```

### Collaboration Primitives

#### Debates
Structured multi-round discussions:

```typescript
const debate = await Orchestrator.createDebate(session.id, initiator, {
  topic: "API Design Approach",
  description: "Should we use REST or GraphQL?",
  participants: ["debater-1", "debater-2"],
  format: "structured", // structured, freeform, tournament, devils_advocate
  maxRounds: 3
})

await Debate.start(debate.id, initiator)
await Debate.submitArgument(debate.id, speaker, {
  position: "pro",
  content: "GraphQL reduces over-fetching",
  evidence: ["Specific data queries", "Single endpoint"]
})
```

#### Voting
Multiple voting strategies supported:

```typescript
const proposal = await Orchestrator.createVote(session.id, proposer, {
  title: "Choose implementation",
  options: [
    { id: "opt1", label: "Option 1" },
    { id: "opt2", label: "Option 2" }
  ],
  votingStrategy: "majority", // majority, unanimous, weighted, ranked
  minVotes: 2
})

await Orchestrator.castVote(proposal.id, voter, "opt1", "Reasoning...")
await Voting.closeProposal(proposal.id, "manual")
```

#### Code Reviews
PR-like review cycles:

```typescript
const review = await Orchestrator.requestReview(session.id, submitter, {
  title: "Review: API Changes",
  artifacts: [
    { type: "code", content: "...", description: "Auth middleware" }
  ],
  reviewers: ["reviewer-1"],
  minApprovals: 1
})

await ReviewCycle.submitReview(review.id, reviewer, {
  verdict: "approve", // approve, reject, request_changes, comment
  comments: [...],
  summary: "LGTM"
})
```

#### MapReduce Jobs
Distributed parallel processing:

```typescript
const job = await Orchestrator.createMapReduceJob(session.id, orchestrator, {
  title: "Refactor codebase",
  inputs: ["file1.ts", "file2.ts", "file3.ts"],
  mapper: "implementer",
  reducer: "integrator",
  maxParallel: 3
})

await MapReduce.startJob(job.id, orchestrator)
```

### Session Management

```typescript
// Get session status
const status = await Orchestrator.getStatus(session.id)

// Format summary
const summary = await Orchestrator.formatSessionSummary(session.id)

// Broadcast message
await Orchestrator.broadcast(session.id, from, "Message", "info")
```

## Database

- **Schema**: Drizzle schema lives in `src/**/*.sql.ts`.
- **Naming**: tables and columns use snake*case; join columns are `<entity>_id`; indexes are `<table>*<column>\_idx`.
- **Migrations**: generated by Drizzle Kit using `drizzle.config.ts` (schema: `./src/**/*.sql.ts`, output: `./migration`).
- **Command**: `bun run db generate --name <slug>`.
- **Output**: creates `migration/<timestamp>_<slug>/migration.sql` and `snapshot.json`.
- **Tests**: migration tests should read the per-folder layout (no `_journal.json`).
